## Ce que j'ai appris

- `/` vs `//` vs `%` : `/` renvoie toujours un float ; `//` arrondit vers le bas (floor), pas vers zéro — piège sur les négatifs (`-7 // 2 == -4`, pas `-3`) ; `%` suit le signe du **diviseur** en Python (contrairement à JS où il suit le dividende). Les trois sont liés par `a == (a // b) * b + (a % b)`.
- `denomination` (vocabulaire finance, pas Python) : la valeur faciale d'un billet/pièce — contraint un montant à être rendu en multiples entiers de cette valeur.
- Sur `exchangeable_value` (Currency Exchange) : deux bugs distincts trouvés en comparant les exemples de la docstring aux résultats réels — (1) le spread doit être un pourcentage **du taux** (`exchange_rate + exchange_rate * spread/100`), pas une addition directe du pourcentage brut ; (2) la fonction doit retourner une **valeur** (nombre de billets × dénomination), pas juste le nombre de billets — bug classique de confondre deux fonctions voisines (`get_number_of_bills` vs `get_value_of_bills`) qui se ressemblent dans leur logique.
- Débug méthodique : comparer les exemples de la docstring à l'exécution réelle (`uv run python3 -c "..."`) pour isoler l'écart avant de retoucher le code.
