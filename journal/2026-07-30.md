## Ce que j'ai appris

- Le rapport entre `uv`, `pip`, `venv` et `pyproject.toml` (et leur mapping avec npm/pnpm/package.json) : uv unifie tout ça en un seul outil, plus besoin de `source .venv/bin/activate`.
- `uv init` a deux layouts : "packagé" (`src/<nom>/`, `[build-system]`, `[project.scripts]`) pour une librairie destinée à être importée/publiée, vs layout plat (`--no-package`) pour un script/bac à sable — je m'y suis repris à 3 fois avant de comprendre pourquoi `src/playground/` apparaissait.
- `curl -LsSf ... | sh` : chaque flag a un rôle (`-L` suit les redirections, `-sS` silencieux sauf erreurs, `-f` échoue proprement sur 4xx/5xx) — et remplacer `| sh` par `| less` pour inspecter un script avant de l'exécuter est une bonne pratique de sécurité.
- `uv` (gestionnaire de projets Astral) et `uvicorn` (serveur ASGI pour FastAPI) n'ont aucun rapport malgré le nom proche — seul point commun : `uvicorn` utilise `uvloop`, basé sur la même `libuv` que Node.
- Exercism CLI : le `download` atterrit toujours dans le workspace configuré (`~/Exercism/`), pas de flag `--path` par exercice — c'est voulu, pour ne pas éparpiller les exos dans des repos perso.
- `pytest` est l'équivalent Python de Jest/Vitest ; `uv run --with pytest pytest` permet de le lancer sans l'ajouter en dépendance permanente d'un dossier hors-projet.
